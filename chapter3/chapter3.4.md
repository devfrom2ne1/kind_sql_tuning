### 3.4.6 결합 인덱스 선택도

- 선택도(Selectivity)란?
	- 전체 레코드 중에서 조건절에 의해 선택되는 레코드 비율

- 인덱스 선택도란?
	- 인덱스 컬럼을 모두 '='로 조회할 때 평균적으로 선택되는 비율

- 선택도(카디널리티)가 높은 인덱스는 생성해도 효용가치가 별로 없다. 
- 결합 인덱스에서 컬럼 간 순서를 정할 때 선택도는 중요하지 않다. 
	- 모두 필수 '=' 조건이면, 어떤 컬럼이 앞으로 오든 인덱스 스캔 효율에 영향을 주지 않는다.

- 하지만, 고객번호는 필수 + 고객등급은 범위검색(or 누락) 조건이라면 → 고객등급을 앞쪽에 두는 것이 유리하다
	- Index Skip Scan이나 IN-List 조건을 활용할 수 있기 때문이다. 
	- 물론 고객등급 조건이 거의 모든 쿼리에 사용되고 값의 종류가 매우 적을(Low Cardinality)때만 사용하는 특수한 경우입니다


### 3.4.7 중복 인덱스 제거

#### 완전중복

```shell
X01 : [계약ID + 청약일자] => 중복!
X02 : [계약ID + 청약일자 + 보험개시일자] => 중복!
X03 : [계약ID + 청약일자 + 보험개시일자 + 보험종료일자]
```

- X03 인덱스가 X01, X02	를 모두 포함하기 때문에, X03만 남기고 나머진 모두 삭제해도 된다.

#### 불완전 중복

```shell
X04 : [계약ID + 보험개시일자]
X05 : [계약ID + 보험종료일자]
X06 : [계약ID + 데이터생성일시]
```

- 만약 '계약ID'를 '='조건으로 조회했을 때, 조회되는 데이터가 5건 뿐이라면? 
	- 인덱스를 여러개 만들 필요가 없다!

#### NDV에 따른 인덱스 중복

| 컬럼명 | NDV |
| :--- | :--- |
| 거래일자 | 2,356 | 
| 관리지점번호 | 127 |
| 일련번호 | 1,850 | 
| 계좌번호 | 5,956 | 
| 종목코드 | 1,715 |
| 결제일자 | 2,356 |

```shell
PK : 거래일자(2,356) + 관리지점번호(127) + 일련번호(1,850)
N1 : 계좌번호(5,956) + 거래일자 (2,356)
N2 : 결제일자(2,356) + 관리지점번호(127)
N3 : 거래일자(2,356) + 종목코드 (1,715)
N4 : 거래일자(2,356) + 계좌번호 (5,956)
```

- **개선안(1)**
	- N3 : 거래일자(2,356) + 종목코드(1,715) **+ 계좌번호(5,956)** => 계좌번호 추가
	- ~~N4 : 거래일자(2,356) + 계좌번호 (5,956)~~= => 삭제

- **개선안(2)**
	- PK : 관리지점번호(127)+ 거래일자(2,356) + 일련번호(1,850) => 순서 변경
	- ~~N4 : 거래일자(2,356) + 계좌번호 (5,956)~~= => 삭제

#### 조건절 없이 인덱스 중복 찾아내기

	- N2 : ~~관리번호(250,782)~~ => 삭제
