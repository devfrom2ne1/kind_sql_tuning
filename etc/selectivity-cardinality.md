# 선택도와 카디널리티


## 1. 카디널리티 (Cardinality)

- 보통 성능 튜닝이나 실행 계획을 볼 때 '카디널리티'는 다음 두 가지 중 하나를 의미합니다.

| 구분 | 의미 | 비고 |
| :--- | :--- | :--- |
| **컬럼 카디널리티** | 특정 컬럼에 들어있는 **중복되지 않은 값의 개수** (NDV, Number of Distinct Values) | 예: '성별' 컬럼의 카디널리티는 2 (남, 여) |
| **실행 계획 카디널리티** | 특정 연산을 수행한 후 결과로 나올 **예상 행 수 (Expected Rows)** | 예: 카디널리티가 5라면, '=' 조건으로 조회했을때 5건이 나옴 |

- 컬럼 카디널리티

	- 컬럼 카디널리티는 특정 컬럼에 포함된 **'서로 다른 값(Unique Values)의 개수'** 를 의미합니다. 
	- 쉽게 말해 **"데이터가 얼마나 중복되지 않고 다양한가?"** 를 수치로 나타낸 것입니다.

	- 높은 카디널리티 (High Cardinality): 주민등록번호, 이메일, 사번처럼 중복이 거의 없고 고유한 값이 많은 경우입니다.
	- 낮은 카디널리티 (Low Cardinality): 성별(남/여), 결제 상태(완료/대기), 학년처럼 데이터 종류가 몇 개 안 되고 중복이 많은 경우입니다.

		> 💡 컬럼 카디널리티가 높을수록 인덱스 효율이 좋습니다.

## 2. 선택도 (Selectivity)

### ① 컬럼 기준의 선택도 (기초 데이터)
* 특정 컬럼에서 하나의 값이 가질 수 있는 평균적인 비율입니다.
* **공식**: 1 / NDV(컬럼 카디널리티)
* 예: 성별 컬럼의 NDV가 2라면, 선택도는 1 / 2 = 0.5(50%)입니다.

### ② 조건절(Predicate)의 선택도
* `WHERE` 조건에 의해 실제 데이터가 걸러지는 비율입니다.
* **공식**: 선택도 = 조건에 맞는 행 수 / 전체 행 수
* 예: 1만 명 중 '대리' 직급이 1,000명이라면, `직급 = '대리'` 조건의 선택도는 0.1(10%)입니다.


## 3. 선택도와 카디널리티의 관계

옵티마이저는 이 숫자들을 가지고 아래 순서대로 계산을 진행하여 최종 실행 계획을 세웁니다.

1.  **통계 정보 확인** : 특정 컬럼의 **NDV(컬럼 카디널리티)** 를 확인합니다.
2.  **선택도 계산** : 1을 이용해 해당 조건의 **선택도** 를 구합니다. ( 1 / NDV )
3.  **최종 결과 도출** : 전체 행 수에 선택도를 곱해 **실행계획 카디널리티(Rows)** 를 구합니다.
    * **공식** : 실행계획 카디널리티 = 전체 행 수/ 선택도

## 4. 실전 예시: '고객' 테이블 분석

전체 데이터가 **100,000건(10만 건)** 인 `CUSTOMERS` 테이블이 있다고 가정해 보겠습니다.

### 예시 A: '고객번호' (PK/Unique 컬럼)
고객번호는 중복이 없는 고유한 값입니다.

* **컬럼 카디널리티 (NDV)** : 100,000 (모든 값이 다름)
* **선택도 (Selectivity)** : 1 / 100,000 = **0.00001 (0.001%)**
* **실행계획 카디널리티 (Rows)** : 100,000 * 0.00001 = **1건**
* **해석** : 특정 고객번호로 조회하면 딱 1건만 나올 것이므로, 옵티마이저는 **Index Unique Scan** 을 선택합니다.

### 예시 B: '거주지역' (중복이 많은 컬럼)
거주지역은 전국 8도/광역시 정도로 분류되어 10종류의 값이 있다고 가정합니다.

* **컬럼 카디널리티 (NDV)** : 10
* **선택도 (Selectivity)** : 1 / 10 = **0.1 (10%)**
* **실행계획 카디널리티 (Rows)** : 100,000 * 0.1 = **10,000건**
* **해석** : 특정 지역(예: 서울)으로 조회하면 1만 건이 나올 것으로 예상됩니다. 이 경우 인덱스를 탈지, Full Scan을 할지 옵티마이저가 비용(Cost)을 따져 결정하게 됩니다.

---

### [참고] 한눈에 비교하기

| 항목 | 예시 A (고객번호) | 예시 B (거주지역) |
| :--- | :--- | :--- |
| **컬럼 카디널리티(종류)** | 매우 높음 (High) | 낮음 (Low) |
| **선택도(비율)** | 매우 낮음 (Low) | 높음 (High) |
| **조회 건수(예상)** | 매우 적음 (1건) | 많음 (10,000건) |
| **인덱스 효율성** | **매우 좋음** | 상대적으로 낮음 |



---

### 💡 튜닝 포인트
* **선택도가 낮을수록(0에 가까울수록)** 해당 컬럼은 인덱스로 만들기 아주 좋은 후보입니다. 
* 반대로 **선택도가 높을수록(1에 가까울수록)** 인덱스를 만들어도 효율이 떨어져서 오라클이 테이블 전체를 읽는(Full Table Scan) 방식을 선호하게 됩니다.
